  <name>Task 1: Create conversation extraction actions (coverage + triggers)</name>
  <files>convex/conversationActions.ts</files>
  <action>
Create `convex/conversationActions.ts` with "use node" directive (needs Anthropic SDK + Zod).

1. **extractCoverage action** — Called after every assistant response to update coverage state:
   ```
   args: { sessionId, phase, recentMessages (last 10 messages as {role, content}[]) }
   ```
   Implementation:
   - Import `createCoverageSchema` and `buildCoverageExtractionPrompt` from the schemas (these are in src/lib but Convex Node actions can import them)
   - Build the Zod schema for the current phase via `createCoverageSchema(phase)`
   - Call Claude with structured outputs:
     ```typescript
     const response = await anthropic.messages.create({
       model: "claude-sonnet-4-20250514",  // Use Sonnet for extraction (cheaper, fast enough)
       max_tokens: 1024,
       system: buildCoverageExtractionPrompt(phase, currentCoverage),
       messages: recentMessages.map(m => ({ role: m.role, content: m.content })),
       // Note: structured outputs via response_format or parsing
     });
     ```
   - IMPORTANT: Check if @anthropic-ai/sdk supports `zodOutputFormat` in this version. If not available, use JSON mode with manual schema enforcement: add the schema as JSON in the system prompt and parse the response with `JSON.parse`. The Zod schema still validates the parsed result.
   - Parse the response, validate with Zod `.safeParse()`
   - Call `ctx.runMutation(internal.conversationState.upsertCoverageState, { sessionId, phase, ...parsedResult })`
   - Return the parsed coverage result (caller may need it for progress bar updates)
   - Wrap in try/catch: if extraction fails, log warning but don't break the conversation flow

2. **detectTriggers action** — Called with each user message to find research opportunities:
   ```
   args: { sessionId, phase, userMessage: string, intensitySetting: "low"|"medium"|"high", searchedSources: string[] }
   ```
   Implementation:
   - Import `TriggerDetectionSchema` and `buildTriggerDetectionPrompt`
   - Call Claude with structured outputs (Sonnet model):
     ```typescript
     system: buildTriggerDetectionPrompt(intensitySetting, searchedSources)
     messages: [{ role: "user", content: userMessage }]
     ```
   - Parse and validate response
   - Filter triggers based on intensity: if intensity is "low", only return triggers with priority "high"
   - Return filtered triggers array
   - Wrap in try/catch: if detection fails, return empty array (don't block conversation)

3. **Both actions use `claude-sonnet-4-20250514`** (not Opus) for cost efficiency. These are background analysis calls, not the main conversation response.

4. **Import pattern**: Since these are Convex Node actions, they can import from `../../src/lib/schemas/` via relative paths or the schemas need to be duplicated in convex/. Prefer: define the Zod schemas inline in this file if import from src/ causes Convex bundling issues. Reference the schema designs from 08-01 but keep the actual Zod definitions co-located with the action for Convex compatibility.

   If Convex Node actions CAN import from src/lib (test this), use imports. If not, duplicate the schema definitions in this file with a comment: `// Schema mirrors src/lib/schemas/coverageExtraction.ts — keep in sync`.
