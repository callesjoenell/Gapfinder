  <name>Task 1: Create conversation state helper module</name>
  <files>src/lib/conversationState.ts</files>
  <action>
Create `src/lib/conversationState.ts` with pure functions that build system prompt sections from conversation state. These are imported by systemPrompts.ts.

1. **Types** — Define the expanded context interface:
   ```typescript
   export interface ConversationContext {
     currentPhase: number;
     sessionPath: "exploration" | "evaluation";
     summaries: Summary[];  // reuse existing Summary type from systemPrompts
     isFirstSession: boolean;  // first session ever for this user
     isNewSession: boolean;  // first message in this session (no messages yet)
     otherSessionNames?: string[];  // names of user's other active sessions
     coverageState: Record<string, string> | null;  // topic -> depth level
     energyLevel: "high" | "moderate" | "low";
     researchIntensity: "low" | "medium" | "high";
     searchedSources: string[];
     researchFindings: Array<{ source: string; query: string }>;  // simplified for prompt
   }
   ```

2. **buildJourneyFraming(context)** — Returns string with:
   - If `isFirstSession && isNewSession`: Full welcome + roadmap. List ALL phases for the path (exploration: 0-3, evaluation: 4-9) with name, description, and timeEstimate from phaseConfig. Include: "Here's what we'll work through together:" then the phase list. End with: "We're starting at Phase {N}: {name}."
   - If `isNewSession` (not first): "Welcome back! You have {N} other sessions going. Let's pick up something new." Then show roadmap.
   - If `!isNewSession` (continuing): "We're in Phase {N}: {name}. {coverage summary}." If user has other sessions: "You're also working on {otherSessionNames.join(', ')} in other sessions."
   - Per LOCKED decision: "Since you've been through {phaseName} before, this will feel familiar" when applicable.
   - Always include time estimates per phase.

3. **buildCoverageMap(phaseNumber, coverageState)** — Returns string showing:
   - List each topic with its depth: "- Life Situation: deep (specific examples shared)"
   - Use symbols for quick scan: not_mentioned, surface, moderate, deep
   - Add summary: "Coverage: X/Y topics at moderate+ depth. {what's missing if any}."
   - If coverageState is null (no extraction yet): "No coverage data yet — this is the start of the conversation."

4. **buildPacingGuidance(energyLevel)** — Returns string per RESEARCH.md Pattern 5:
   - high: Match energy, explore depth, 1-2 questions max, mirror message length
   - moderate: Moderate responses, gentle topic shifts if depleted, 1 open question
   - low: Brief focused responses, summarize + bridge, 1 direct question, match brevity

5. **buildResearchIntensityGuidance(intensity, searchedSources)** — Returns string:
   - low: "Only flag major unsupported claims (e.g., 'everyone wants X')"
   - medium: "Flag claims, competitor mentions, and clear pain points"
   - high: "Flag everything including implicit assumptions"
   - Always append: "Already searched: {sources}. Don't re-suggest these."
   - Per LOCKED: "When suggesting research, offer 2-3 options. Always ASK first, never auto-trigger."

6. **buildResearchReferenceGuidance(findings)** — Returns string for referencing past research:
   - If findings exist: "Reference these findings inline. Quote key points AND point to Research panel for details."
   - List what has been searched: "{source}: {query}" for each finding
   - Per LOCKED: "Be honest when results are empty. Don't interpret empty results."

7. **inferEnergyLevel(recentMessages)** — Takes last 3-5 messages, returns energy level:
   - Simple heuristic (not Claude call): average user message length
   - Short (< 50 chars) = low, medium (50-200 chars) = moderate, long (> 200 chars) = high
   - Also check: if last 2 user messages are shorter than previous ones = energy dropping
   - This is a rough heuristic; the structured extraction in Plan 03 will provide more accurate assessment
