  <name>Task 2: Add phase-aware turn pacing and coverage extraction</name>
  <files>scripts/simulate-chat.mjs</files>
  <action>
Enhance the conversation loop with intelligent turn pacing and coverage extraction.

**Turn Pacing Per Phase:**
Instead of a flat MAX_TURNS limit, implement phase-aware pacing:
- Define turn budgets: `{ 0: [15, 18], 1: [12, 15], 2: [10, 12], 3: [8, 10], 4: [8, 10], 5: [8, 10] }`
- Track turns within current phase
- When turn count reaches the minimum for a phase and no natural transition has occurred, append to Marcus's system prompt: "You've been in this phase for a while. If the conversation feels ready to move on, agree when Gap Finder suggests it."
- When turn count exceeds the maximum, append to Gap Finder's system prompt: "The user has been in this phase for ${count} turns. If coverage criteria are reasonably met, consider suggesting a transition to the next phase."
- Total conversation ends after Phase 5 completes or after 80 turns total (safety limit)

**Coverage Extraction (after each Gap Finder response):**
After each Gap Finder response, call Claude (quick, cheap call) to extract coverage updates:
- Send the last 2 messages (Marcus's message + Gap Finder's response)
- Ask Claude to assess which coverage topics were touched and to what depth
- Use the current phase's coverageTopics from phaseConfig
- Merge results into coverageState (only upgrade depth, never downgrade): not_mentioned < surface < moderate < deep
- Format: JSON with topic_key → depth_level mapping

The coverage extraction prompt should be:
```
Given this exchange in Phase {N} ({phaseName}), assess which topics were covered and to what depth.

Topics for this phase:
{list of coverageTopics with key, label, description}

Last exchange:
User: {marcus message}
Assistant: {gap finder response}

Current coverage state:
{current coverageState}

Return JSON mapping topic keys to depth levels. Only include topics that were touched in this exchange. Depth levels: "surface" (brief mention), "moderate" (discussed with some specifics), "deep" (detailed exploration with examples/evidence).

Return ONLY the JSON object, no other text.
```

Use claude-sonnet-4-5-20250929 with max_tokens: 256 for these extraction calls (fast and cheap).

Merge logic: for each topic in the extraction result, compare with existing coverage. Keep the deeper level:
```js
const DEPTH_ORDER = { not_mentioned: 0, surface: 1, moderate: 2, deep: 3 };
// Only upgrade, never downgrade
if (DEPTH_ORDER[newDepth] > DEPTH_ORDER[currentDepth]) coverageState[key] = newDepth;
```

Print coverage state after extraction: "[coverage: life_situation=deep, profession=moderate, hobbies=surface, ...]"
